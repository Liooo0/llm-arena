# LLM Arena 选型报告 · 2026-08

**问题：生产环境默认模型应该选谁？Flash 还是 Pro？**

本报告基于 3 轮真实对战数据（2026-08-04 / 08-10 / 08-19），共 **63 题、181 次模型调用**，给出模型选型结论。所有数据可复现，原始 JSON 在 `reports/` 下。

## 二、Flash vs Pro 直接对比（08-19 轮，10 题 × 2 模型）

### 2.1 耗时与 token

| 指标 | deepseek-v4-flash | deepseek-v4-pro | 差距 |
|---|---|---|---|
| 平均耗时 | **24.2s** | 38.2s | flash 快 **58%** |
| P90 耗时 | **36.7s** | 47.6s | flash 低 11s |
| 平均 total_tokens | **1385** | 2233 | pro 多 **61%** |
| 成功率 | 10/10 | 10/10 | 平 |

> 注意：本轮 opencode 通道代理波动较大（flash 单题 15s~41s），绝对值会随网络变化；**相对差（flash 快约 1.6 倍、token 省约 1.6 倍）跨轮次稳定**。

### 2.2 逐题质量对比

| # | 方向 | 题目 | flash | pro |
|---|---|---|---|---|
| Q01 | 代码评审 | 缓存过期/并发一致性 | 同等覆盖（含时钟回拨细节） | 同等覆盖 |
| Q02 | 代码评审 | 用户输入拼 system prompt | 覆盖更全（合规角度+修复代码） | 覆盖核心风险 |
| Q03 | 模型选型 | 级联路由策略 | 同等（给架构图+置信度阈值） | 同等 |
| Q04 | 模型选型 | P95<3s 低延迟架构 | 同等（TTFT/TPOT 拆解） | 同等 |
| Q05 | Agent 编排 | 引导并行工具调用 | 点出「LLM 不执行工具」底层事实 | 给可直接落地的规则 |
| Q06 | Agent 编排 | triage 路由 Agent | 覆盖更全（多信号融合+fallback） | 结构化输出更清晰 |
| Q07 | RAG 调优 | query 改写策略 | 覆盖更全（3 痛点+HyDE 场景） | 精简但到位 |
| Q08 | RAG 调优 | Text-to-SQL vs RAG | 同等（选型判断维度表） | 同等 |
| Q09 | prompt 设计 | 苏格拉底式导师 | 同等 | 规则更硬（拒绝直接回答） |
| Q10 | prompt 设计 | 提示注入防御 | 同等 | 同等 |

**结论：10 题无一出现质量碾压。** pro 在 Q09 的规则设计略硬、Q05 的落地性略好，flash 在 Q02/Q06/Q07 的覆盖面更全。**多数题目打平。**

### 2.3 成本换算（结合官方定价）

官方 2026-08-17 峰谷定价（元/百万 tokens，空闲时段）：

| | Flash | Pro | 倍数 |
|---|---|---|---|
| 输入（缓存未命中） | 1.5 | 4.5 | 3× |
| 输出 | 4.5 | 13.5 | 3× |

**实际任务成本**（以本轮 10 题平均 token 计算，空闲时段）：

| | Flash | Pro |
|---|---|---|
| 单题平均 tokens | 1385 | 2233 |
| 估算输入 tokens | ~800（题面+system） | ~800 |
| 估算输出 tokens | ~585 | ~1433 |
| **单题成本** | **0.8×1.5 + 585×4.5/1e6 ≈ 0.0039 元** | **0.8×4.5 + 1433×13.5/1e6 ≈ 0.0234 元** |
| **成本倍数** | **1×** | **约 6×** |

> 简化估算：输入按题面+system 约 800 tokens（两模型相同），输出按实测均值差。真实差距在 **5~6 倍**——不是官方标价的 3 倍，因为 pro 输出 token 更多。

## 三、跨模型全景（08-04 + 08-10 轮）

| 模型 | 成功率 | 平均耗时 | 平均 token | 质量小胜题数 | 定位 |
|---|---|---|---|---|---|
| **deepseek-v4-flash** | 30/30（100%） | **22.4s** | **1351** | 6/30 | 效率之王 |
| deepseek-v4-pro | 10/10（100%） | 38.2s | 2233 | —（vs flash 打平） | 深度推理 |
| qwen3.7-max | 29/30（96.7%） | 46.4s | 1803 | **8/30** | 单答质量上限最高 |
| glm-5.2 | 30/30（100%） | 46.4s | 1700 | 5/30 | 方案完整但尾延迟差 |
| qwen3.8-max-preview | 20/20（100%） | 25.3s | 1113 | 3/20 | 国内直连备选 |
| deepseek-v4-flash-0731 | 20/20（100%） | **12.7s** | 1762 | 4/20 | 国内直连·最快 |

**两个重要发现：**

1. **flash 质量不输 pro**（08-19 轮 10 题打平），但快 58%、省 61% token、成本约 1/6——**生产默认毫无疑问选 flash**。
2. **qwen3.7-max 单题质量上限最高**（08-10 轮小胜 8 题），但慢 2 倍、有失败记录。定位：**高价值单次复杂方案设计**才值得升级。

## 四、选型结论

| 场景 | 推荐模型 | 原因（数据支撑） |
|---|---|---|
| 日常问答 / 客服 | **Flash** | 快 58%、token 省 61%，质量与 Pro 打平（08-19 轮 10 题无碾压） |
| 结构化抽取 / 批量处理 | **Flash** | 高吞吐优势（08-10 轮 26/30 题最快），成本约 Pro 的 1/6 |
| 高吞吐任务（投递/标注/回复） | **Flash** | 100% 成功率（30/30），P90 稳定 32s |
| 复杂推理 / 深度核验 | **Pro** | 单答深度略优（Q09 规则硬约束、Q05 落地性），成本可接受（低频） |
| Coding / 代码评审 | **Pro / Flash 均可** | 08-19 轮 Q01/Q02 打平；pro 未形成碾压 |
| 高价值复杂方案设计 | **qwen3.7-max** | 08-10 轮小胜 8 题，单答质量上限最高；接受 2 倍延迟 |
| 代理抖动降级 | **deepseek-v4-flash-0731**（阿里直连） | 08-04 轮 40/40 零失败，速度最快 12.7s |

**一句话结论：Flash 是生产默认，Pro 是低频兜底，qwen 旗舰是高价值场景的彩蛋。**
